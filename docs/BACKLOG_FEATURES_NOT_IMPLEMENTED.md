# Фичи из анализа конкурентов POS/ERP/RMS, ещё не реализованные в проекте

Источник: *Анализ конкурентов POS/ERP/RMS для общепита в РФ/СНГ и приоритетный план функций для продукта-лидера* (PDF).  
Обозначения: **Priority** = must / should / could; **Complexity** = low / medium / high.

---

## Платформа

| № | Функция | Что реализовать | Priority | Complexity |
|---|---------|------------------|----------|------------|
| 1 | **Multi-tenant модель (полная иерархия)** | Иерархия: holding → бренд → юр.лицо → точка → склад/цех; изоляция данных и конфигураций; лимиты ресурсов. Сейчас есть уровень «ресторан», без полноценной сети/холдинга. | must | high |
| 2 | **RBAC + шаблоны ролей** | Роли: кассир / официант / менеджер / кладовщик / технолог / бухгалтер / маркетолог / франчайзи; шаблоны прав по форматам. Сейчас — базовая авторизация без детального RBAC. | must | medium |
| 3 | **ABAC для сетей/франшиз** | Атрибуты «видит только свои точки/регион/бренд»; матрица прав на справочники и отчёты. | should | high |
| 4 | **Журнал аудита (audit log)** | Любое изменение меню/цен/акций/остатков/прав/возвратов/коррекций; экспорт для проверки. Частично есть ActivityLog — нужна полнота и экспорт. | must | medium |
| 5 | **Offline-first engine** | Локальные транзакции, очередь событий, конфликт-резолвер (последовательность/версионирование), ручной merge в спорных кейсах. | must | high |
| 6 | **Управление устройствами** | Реестр терминалов/KDS/киосков/принтеров; удалённая активация, блокирование, политики обновлений. | must | medium |
| 7 | **Обновления без простоя** | Канареечные релизы для cloud, staged rollouts на edge; «safe mode» при фатальных ошибках. | must | high |
| 8 | **Observability + SLA** | Метрики: задержки POS, очередь кухни, синхронизация, API; отчёты для клиентов по SLA. | must | medium |
| 9 | **Публичный API + Webhooks** | REST/GraphQL для справочников и заказов; webhooks статусов заказов/оплат/возвратов; sandbox. Сейчас API есть, но без документированных webhooks и sandbox. | must | high |
| 10 | **SDK / плагинная модель (Marketplace)** | Плагины печати, интеграций, отчётов; контракт версий. | should | high |

## POS

| № | Функция | Что реализовать | Priority | Complexity |
|---|---------|------------------|----------|------------|
| 11 | **Сценарии обслуживания зала (полные)** | План зала, курсы подачи, модификаторы, split bill, чаевые, банкет/резерв. Частично: зал, столы, split bill есть; нет курсов подачи, чаевых как сущности, банкета. | must | high |
| 12 | **Сценарии QSR (фастфуд)** | Быстрый заказ, комбо, очередь, экран клиента/электронная очередь, предзаказ. | must | medium |
| 13 | **Оплаты и типы оплат** | Наличные/карта/SBP/депозит/сертификаты/частичная оплата; кастомные типы. Сейчас есть разметка оплат по слотам (QR и т.д.), но не полноценный мультитип оплат и сертификаты. | must | high |
| 14 | **Фискальный контур 54‑ФЗ** | Поддержка чеков: предоплата/аванс/кредит/частичный расчёт/коррекция; «чек до оплаты» для общепита (с 01.03.2025); e-чек. Сейчас фискализации нет. | must | high |
| 15 | **Маркировка «Честный знак»** | Разрешительный режим, офлайн-проверка (локальный модуль), запреты продаж, UX подсказки кассиру. | must | high |
| 16 | **Алкогольный контур (ЕГАИС)** | Продажа, списание, приёмка; UX статусы УТМ. | must* | high |
| 17 | **Ветеринарный контур (ВетИС «Меркурий»)** | Приёмка/гашение ВСД, статусы API, очередь при недоступности шлюза. | must* | high |

\* Если ресторан продаёт алкоголь / поднадзорные товары.

## Уже реализовано (для контекста)

- Multi-tenant на уровне ресторана, TenantContext.
- Заказы (создание, закрытие, отмена, разбивка счёта, метки оплат по слотам).
- Брони (активности, филиалы, календарь, тарифы, ценообразование).
- Меню: блюда, категории, опции/модификаторы, рецепты/ингредиенты.
- Склад: остатки, движения, загрузка из Excel.
- Зал: зоны, столы, карта зала, активы, бронирование столов.
- Тарифы: планы, правила, календарь, особые даты, калькулятор цен.
- Смены и шаблоны смен, запросы на обмен.
- CRM/лояльность: гости, бонусы, тиры, кампании, сегменты, RFM, геймификация (миссии, достижения), персональные офферы.
- Прогноз: ML-модуль (выручка/брони, месячный rollup, планировщик).
- Аналитика: отчёты по бронированиям, интеграция с прогнозом в разделе тарифов.
- Telegram: заказы, магазин, оплата по QR.
- QR-меню и публичное заказное меню (сессии).
- Платформа: список ресторанов, роли пользователей.
- Журнал действий (Activity Log).
- Импорт/экспорт заказов и броней в CSV.
- Outbox для событий, rate limiting, внутренний JWT для forecast.
